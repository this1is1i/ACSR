# QA 问答版本追踪规则

> 确保每个 QA 问答条目与其对应的代码版本绑定，通过 git 提交编号实现时效性追溯。

## 触发规则

**每次 git 提交时**，检查本次提交涉及的改动是否影响已有 QA 问答的正确性。如有影响，更新对应 Q# 的 git 提交编号。

触发场景：
- `git commit` 后，sweep 本次 diff 涉及的功能模块
- 对照 QA 文件索引，找到相关 Q#，判断回答内容是否需要更新
- 若内容更新 → 同步更新该 Q# 的 hash 为本次提交
- 若内容无需更新（代码改动不改变 Q 的结论）→ hash 保持不变

## Hash 标注格式

每个 Q# 标题行末尾追加 `（git: <short_hash>）`：

```markdown
## Q37: 密码加密机制与测试账号密码（2026-06-07）（git: c513ad2）
```

- `<short_hash>` 为 `git log --oneline` 的 7 位短 hash
- hash 指向该回答**最近一次被验证/更新时的代码版本**
- 回答内容在此 hash 版本上是准确的；后续提交可能使其过时

## 标注原则

| 场景 | 操作 |
|------|------|
| 新增 Q | 标注当前提交 hash |
| 编辑已有 Q 的内容 | 更新为本次提交 hash |
| 代码改动但 Q 结论不变 | hash 保持不变（无需编辑 Q） |
| 旧的 Q（创建时未标注） | 标注为上一提交的 hash，不再向前回溯 |
| 一个 Q 被多次修改 | hash 始终为最近一次修改该 Q 的提交 |

## QA 文件索引

| 文件 | Q# 范围 | 时间跨度 |
|------|---------|---------|
| `docs/QA_2026-05-16_2026-06-02_v1.md` | Q0 – Q16 | 2026-05-16 → 2026-06-02 |
| `docs/QA_2026-06-02_2026-06-05_v2.md` | Q17 – Q37 | 2026-06-02 → 2026-06-07 |

## 时效性说明

- QA 回答**仅对其标注的 hash 版本代码绝对可靠**
- 读者可通过 `git diff <hash>..HEAD` 查看自上次验证以来的代码变更，自行判断回答是否仍适用
- 未标注 hash 的 Q 视为内容可能已过期，需要优先核实
